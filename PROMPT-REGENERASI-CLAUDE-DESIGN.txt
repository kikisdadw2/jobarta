## PRIORITAS TERTINGGI — BACA SEBELUM APA PUN

Project ini mungkin masih terikat ke design system bawaan bernama "Industry"
(palet mauve-taupe, font Barlow / Barlow Condensed, latar #d4d4d7).
Design system itu MUST diabaikan sepenuhnya.
Token di bawah adalah SATU-SATUNYA sumber kebenaran. Jika ada konflik,
token di bawah MENANG.

NEVER pakai font Barlow atau Barlow Condensed. Font terkunci: Lexend + Source Sans 3.
NEVER pakai #5980a6, #416180, #9c5145, #1d1f20, #d4d4d7, #f2f2f3 — itu token Industry.
NEVER diam-diam mengganti token ini dengan design system project. Kalau kamu
merasa terikat sistem lain, tetap pakai token di bawah DAN sebutkan konfliknya
dalam satu baris di akhir jawabanmu.

Catatan penting supaya tidak salah paham: palet JOBARTA memang berdasar warna
KREM HANGAT. Itu BUKAN palet Industry. Yang dilarang adalah nilai hex Industry
di atas dan font Barlow — bukan kehangatan warnanya.

Verifikasi mandiri sebelum menyatakan selesai:
- string "Barlow" MUST tidak muncul sama sekali di hasilmu
- string "#4B6587" MUST muncul
- warna latar halaman mode terang MUST #F0E5CF

## Design system JOBARTA — patuhi persis, jangan improvisasi

KONTEKS PRODUK
JOBARTA: platform cari kerja berbasis PETA INTERAKTIF untuk Jakarta.
Pengguna: pencari kerja Indonesia (banyak lulusan SMA/SMK, pekerja informal, UMKM),
mayoritas akses lewat HP Android kelas menengah, koneksi 4G tidak stabil.
Nada: tepercaya, jelas, merakyat — BUKAN startup genit, BUKAN korporat kaku.
Bahasa antarmuka: Bahasa Indonesia.

POSISI STRATEGIS: KEPERCAYAAN ADALAH FITUR UTAMA
Risiko terbesar produk ini adalah lowongan palsu & penipuan kerja. Jadi sinyal
kepercayaan (badge terverifikasi, nama perusahaan asli, tombol lapor,
transparansi gaji) BUKAN hiasan — itu inti desain. Tampilkan menonjol.

PATTERN: Marketplace / Directory
- Search bar ADALAH CTA utama. Kurangi friksi menuju pencarian.
- Urutan section landing: Hero (fokus search) -> Kategori -> Lowongan Unggulan
  -> Kepercayaan/Keamanan -> CTA perusahaan.

STYLE: Accessible & Ethical
High contrast, teks besar (min 16px), fokus terlihat jelas, WCAG AA ke atas,
semantik, ramah pembaca layar. Mendukung light mode DAN dark mode penuh.

WARNA — MODE TERANG (pakai token, jangan hex mentah di komponen)
  --color-background   #F0E5CF   krem hangat — LATAR HALAMAN
  --color-surface      #F7F6F2   off-white — kartu, panel, input
  --color-border       #C8C6C6   abu netral — 1,6:1, HANYA garis pemisah
  --color-primary      #4B6587   slate — aksi, link, header — 5,5:1
  --color-on-primary   #F7F6F2
  --color-foreground   #2E3A4D   teks isi — 10,6:1 (AAA)
  --color-accent       #3F6B4F   hijau teredam — TERVERIFIKASI & CTA lamar — 5,7:1
  --color-destructive  #9E3B3B   bata teredam — error, tombol lapor — 6,2:1
  --color-ring         #4B6587   focus ring

  Teks putih di atas: #4B6587 = 6,0:1 · #3F6B4F = 6,1:1 · #9E3B3B = 6,7:1 — semua ✅
  #4B6587 di atas latar krem #F0E5CF = 4,8:1 ✅

WARNA — MODE GELAP
  --color-background   #23211E      --color-foreground   #F0E5CF   12,9:1
  --color-surface      #2E2B26      --color-accent       #7FB68C    6,9:1
  --color-border       #4A453D      --color-destructive  #E08585    6,0:1
  --color-primary      #8FA8C8      --color-on-primary   #23211E
  --color-ring         #8FA8C8      (primary 6,6:1)

EMPAT ATURAN WARNA YANG MENGIKAT SEMUA HALAMAN — jangan dilanggar
1. #C8C6C6 NEVER memikul makna. Ia garis dan pemisah — bukan teks, bukan ikon,
   bukan label nonaktif. Teks nonaktif pakai #4B6587 dengan opacity, bukan abu.
2. Hijau #3F6B4F memikul DUA peran sekaligus: badge TERVERIFIKASI dan CTA
   "Lamar Sekarang". Itu disengaja — keduanya berarti "aman", dan pengguna
   sasaran belajar warna lebih cepat daripada ikon.
3. Merah #9E3B3B NEVER dipakai selain untuk error dan pelaporan. Jangan dipakai
   sebagai warna dekoratif betapapun cocoknya dengan krem.
4. Latar #F0E5CF dan permukaan #F7F6F2 cuma beda 1,16:1 — terlalu tipis untuk
   jadi satu-satunya pemisah. Kartu MUST punya garis #C8C6C6 ATAU bayangan
   halus, NEVER mengandalkan beda warna saja.

TIPOGRAFI
Judul: Lexend (300/400/500/600/700)
Isi:   Source Sans 3 (300/400/500/600/700)
Skala: 12 · 14 · 16 · 18 · 24 · 32 · 40
Body minimal 16px di mobile. Line-height 1.5–1.75. Panjang baris 60–75 karakter.
Angka dalam kolom/tabel pakai tabular-nums. Judul pakai text-wrap: balance.

SPASI & LAYOUT
Ritme 8pt: 4 · 8 · 16 · 24 · 32 · 48.
Mobile-first. Breakpoint yang MUST digambar: 375px (utama) dan 1440px (desktop).
Target sentuh minimal 44x44px, jarak antar target minimal 8px.
Layout full-bleed MUST hormati env(safe-area-inset-*).

IKON
SVG saja — Lucide atau Heroicons, stroke konsisten.
NEVER pakai emoji sebagai ikon struktural.

GERAK
Transisi 150–300ms, ease-out saat masuk. Hanya animasikan transform & opacity.
NEVER transition: all. Sediakan varian prefers-reduced-motion.

MENULIS TEKS (UI copy)
Bahasa Indonesia, kalimat aktif, sapa pengguna dengan "kamu".
Label tombol spesifik: "Lamar Sekarang" bukan "Kirim"; "Cari Lowongan" bukan "Submit".
Pesan error MUST berisi CARA MEMPERBAIKI, bukan cuma menyatakan salah.
Angka pakai numeral (3 lowongan, bukan tiga lowongan).
Pakai elipsis "…" bukan "...", kutip melengkung, dan &nbsp; untuk "10&nbsp;km".
Teks loading diakhiri "…".
Format mata uang: Rp 4.500.000 (Intl.NumberFormat, locale id-ID).
Tanggal/waktu: Intl.DateTimeFormat. Nama brand & kode: translate="no".

RESPONSIF & KESEDERHANAAN — dua aturan yang tidak boleh dilanggar
1. "Sederhana" berarti SEDIKIT ELEMEN — NEVER elemen yang dikecilkan, disamarkan,
   atau dihilangkan labelnya. Kesederhanaan NEVER mengalahkan keterbacaan.
2. Responsif berarti mengubah SUSUNAN — NEVER sekadar mengecilkan layout desktop.

RESPONSIF
- Gambar tiap layar di DUA lebar saja: 375px dan 1440px.
- Layar penuh MUST pakai 100dvh, NEVER 100vh. Bilah alamat Chrome Android
  mengubah tinggi viewport saat scroll; 100vh membuat bottom sheet dan tombol
  peta terpotong.
- Dua kolom di 1440px MUST menjadi satu kolom bertumpuk di 375px.
- NEVER ada scroll horizontal yang tidak disengaja di lebar mana pun.
- Teks panjang MUST punya perilaku yang digambar: elipsis, line-clamp, atau
  membungkus. Gambar kondisi TERPANJANGNYA, bukan teks contoh yang kebetulan pas.
  Anak flex MUST punya min-width: 0 supaya bisa terpotong.
- Tabel/daftar lebar di layar kecil MUST scroll horizontal di dalam wadahnya
  sendiri ATAU berubah jadi kartu.

KESEDERHANAAN
- Satu aksi utama per layar. Aksi lain tetap ada, tapi lebih rendah secara visual.
- Buang hiasan tanpa informasi: bingkai ganda, bayangan bertumpuk,
  kartu di dalam kartu, garis pemisah yang tidak memisahkan apa pun.
- Ruang putih adalah alat pemisah utama — NEVER garis dan kotak sebagai default.
- Uji tiap elemen: kalau dihapus dan tidak ada makna yang hilang, hapus.
- NEVER dikorbankan atas nama "bersih": ukuran teks (isi min 16px), kontras,
  label field yang terlihat, teks pendamping ikon, target sentuh 44px.

HINDARI
Desain kekanak-kanakan · gradien ungu/pink ala AI · glassmorphism berat ·
animasi dekoratif tanpa makna · abu-abu di atas abu-abu · teks < 12px ·
warna sebagai satu-satunya penanda makna · ikon tanpa label ·
teks abu tipis sebagai "estetika" · label yang hanya hidup di placeholder ·
tipografi tipis untuk teks isi · font Inter/Roboto/Arial.

## GATE ACCEPTANCE — Web Interface Guidelines
Sebelum menyatakan desain selesai, jawab ya/tidak untuk SETIAP baris.
Semua MUST bernilai aman. Kalau ada yang gagal, perbaiki dulu, jangan diserahkan.

AKSESIBILITAS
- Tombol ikon-saja punya aria-label?
- Setiap kontrol form punya label terlihat yang bisa diklik (htmlFor / membungkus)?
- Ikon dekoratif ditandai aria-hidden="true"?
- Gambar punya alt (atau alt="" bila dekoratif) DAN width/height eksplisit?
- Hierarki heading h1->h6 runtut, tidak melompat? Ada skip link ke konten utama?
- Elemen aksi pakai <button>, navigasi pakai <a>/<Link> — bukan <div onClick>?
- Perubahan status asinkron (unggah, hasil filter) diumumkan aria-live="polite"?
- Media bermakna punya caption/transkrip?

FOKUS
- Setiap elemen interaktif punya focus ring TERLIHAT, 3–4px, token --color-ring?
- Tidak ada outline-none tanpa pengganti? Pakai :focus-visible, bukan :focus?
- Kontrol majemuk pakai :focus-within?
- Overlay/sticky tidak menutupi elemen yang sedang fokus?

FORM
- Input punya autocomplete, name bermakna, type & inputmode yang benar?
- Placeholder diakhiri "…" dan TIDAK menggantikan label?
- Paste tidak pernah diblokir?
- Spellcheck dimatikan pada email/kode/username?
- Checkbox & radio berbagi satu target sentuh dengan labelnya?
- Tombol submit aktif sampai request mulai, lalu spinner?
- Error tampil INLINE di bawah field, fokus lompat ke error pertama?
- Ada peringatan sebelum meninggalkan halaman dengan perubahan belum tersimpan?

GERAK
- Hormati prefers-reduced-motion? Hanya transform & opacity? Tidak ada transition: all?
- transform-origin benar? Animasi bisa diinterupsi?
- Autoplay >5 detik punya kontrol jeda?

TIPOGRAFI & KONTEN
- Pakai "…" bukan "..."? Kutip melengkung? &nbsp; pada "10 km", "5 MB"?
- tabular-nums pada kolom angka? text-wrap: balance pada judul?
- Wadah teks tahan isi panjang (truncate / line-clamp / break-words)?
- Anak flex punya min-w-0? Empty state digambar?
- Input pendek, sedang, dan SANGAT panjang sudah diantisipasi?

SENTUH & LAYOUT
- Target sentuh >=44x44px, jarak >=8px?
- touch-action: manipulation? overscroll-behavior: contain pada modal/drawer?
- Setiap gestur geser punya alternatif tap DAN keyboard?
- Full-bleed hormati env(safe-area-inset-*)? Tidak ada scrollbar tak disengaja?
- Layout pakai flex/grid, bukan pengukuran JS?

DARK MODE & LOKAL
- color-scheme: dark diset? meta theme-color cocok dengan latar?
- <select> native diberi background-color & color eksplisit?
- Tanggal via Intl.DateTimeFormat, angka/mata uang via Intl.NumberFormat?

NAVIGASI
- URL mencerminkan state (filter, tab, paginasi, panel) supaya bisa di-share?
- Aksi destruktif punya konfirmasi atau undo?

COPY
- Kalimat aktif, orang kedua ("kamu"), label tombol spesifik?
- Pesan error menyebut sebab DAN langkah perbaikan?
- Angka pakai numeral?

CHECKLIST TERAKHIR SEBELUM SELESAI — semua MUST "tidak"
- Ada teks isi < 16px?
- Ada field tanpa label terlihat?
- Ada ikon tanpa teks pendamping?
- Ada lebih dari satu aksi utama dalam satu layar?
- Ada scroll horizontal di 375px?
- Susunan 375px cuma versi kecil dari 1440px?
- Ada makna yang dibedakan HANYA oleh warna?
- Ada kemunculan kata "Barlow"?

Artboard yang dibuat:

2. Tipografi — contoh nyata semua ukuran skala (12–40) dengan teks Bahasa
   Indonesia ASLI, bukan lorem ipsum. Tunjukkan judul, subjudul, body, caption,
   label. Sertakan contoh tabular-nums pada deret gaji dan contoh text-wrap:
   balance pada judul panjang.

   focus, active, disabled, loading). Focus ring MUST terlihat jelas 3–4px.
   Sertakan varian lebar penuh untuk 375px dan tombol ikon 44x44px ber-aria-label.

   checkbox, file upload. Masing-masing dengan state: kosong, terisi, fokus, error.
   Label MUST selalu terlihat di atas field — NEVER placeholder-only.
   Error tampil inline di bawah field, berisi cara memperbaiki.
   Slider MUST menampilkan nilainya sebagai angka, bukan cuma posisi handle.
5. Kartu Lowongan (JobCard) — komponen paling penting di produk ini. 4 varian:
   (a) normal, (b) perusahaan terverifikasi, (c) gaji disembunyikan
   ("Gaji dirundingkan" — jangan biarkan kosong menggantung),
   (d) judul & nama perusahaan SANGAT panjang untuk menguji truncation.
   Isi: judul, nama perusahaan + badge, jarak ("2,4 km dari kamu"), gaji,
   tipe kerja, waktu posting.
6. Badge & Status — TERVERIFIKASI (hijau), Menunggu Verifikasi (kuning),
   Ditolak (merah), dan status lamaran: Dikirim -> Dilihat -> Wawancara ->
   Diterima/Ditolak. Setiap status MUST dibedakan oleh IKON + TEKS,
   NEVER warna saja (buta warna).
7. Empty State — 3 skenario: belum ada lowongan di area ini, belum ada lamaran,
   pencarian tidak menemukan hasil. Masing-masing: ilustrasi sederhana +
   penjelasan + satu tombol tindakan lanjutan.

Aturan tambahan:
- Beri nama setiap komponen PERSIS seperti nanti di kode
  (JobCard, StatusBadge, MapPicker, RadiusSlider, CVUpload, ConsentCheckbox).
- Sertakan catatan spasi (padding/gap) dalam ANGKA, supaya bisa langsung
  diterjemahkan ke kode.

DESIGN 3B — LENGKAPI PROFIL
================================================================================
[TEMPEL BLOK A DI ATAS DULU]

Desain layar "Lengkapi Profil" — SETELAH onboarding pilih peran (DESIGN 3).

PRINSIP PENGIKAT — baca sebelum menggambar apa pun:
Momen "aha" seeker JOBARTA BUKAN "punya CV", melainkan MELIHAT LOWONGAN NYATA
DI DEKAT RUMAHNYA. Jadi layar ini NEVER boleh terasa berdiri di antara login
dan peta. Konsekuensi desain:
- NEVER gambar indikator langkah "3 dari 3" di sini. Itu membingkai layar
  opsional sebagai kewajiban dan menaikkan drop-off.
- Unggah CV didesain JUST-IN-TIME: pemicu utamanya saat seeker menekan "Lamar"
  pertama kali (artboard 5), bukan penghalang sebelum melihat peta.
- Di layar ini CV hanya ditawarkan sebagai quick win opsional, dengan jalan
  keluar jelas.

Artboard (375px dan 1440px, light DAN dark mode):

1. Lengkapi Profil — Seeker
   • Header: "Sedikit lagi, [Nama]" + manfaat konkret, bukan instruksi
     ("Perusahaan lebih sering membalas pelamar yang profilnya lengkap").
   • Avatar bulat besar, prefill foto Google, tombol "Ganti foto" bertumpang.
     Rasio & ukuran terkunci — ruangnya sudah dipesan sebelum gambar termuat,
     supaya tidak ada pergeseran layout.
   • Nama: field TERISI dari Google, BISA DIUBAH. Label terlihat di atas field
     dan bisa diklik untuk memfokuskan field.
     Hint kecil: "Pakai nama seperti di lamaran kerja."
     NEVER gambar field ini dalam keadaan ter-autofocus — di mobile itu
     memunculkan keyboard dan menutup separuh layar.
   • CV sebagai kartu quick-win opsional: "Punya CV? Unggah sekarang (30 detik)"
     + teks kecil "atau nanti saat kamu melamar".
   • CTA utama "Simpan & Lihat Lowongan" — nama tombol menyebut HASILNYA.
   • Jalan keluar "Nanti saja" sebagai tombol teks terbaca jelas
     (kontras >=4,5:1, target >=44px). NEVER abu-abu samar. NEVER dark pattern.

2. Lengkapi Profil — Employer
   Varian sama TANPA bagian CV. Hanya foto + nama, lalu arah ke verifikasi
   perusahaan. Gambar berdampingan dengan artboard 1 agar bedanya terlihat.

3. Dropzone CV — anatomi lengkap
   Dropzone NEVER hanya area seret-lepas. MUST ada tombol "Pilih berkas" di
   dalamnya sebagai jalur setara untuk tap & keyboard — seret-lepas mustahil
   di HP dan tidak bisa dipakai pengguna keyboard.
   • Batas & format disebut SEBELUM memilih ("PDF, DOC, atau DOCX · maks 5&nbsp;MB"),
     bukan muncul sebagai error sesudahnya.
   • Gambar state fokus keyboard pada dropzone (focus ring 3–4px, --color-ring).

4. Tiga state unggah dalam satu artboard, bertumpuk:
   a. Sedang mengunggah — nama berkas, progres %, tombol Batalkan.
      Teks status diakhiri elipsis: "Mengunggah…". Di 4G, 5&nbsp;MB terasa lama;
      tanpa progres user mengira aplikasi hang.
   b. Berhasil — nama berkas, ukuran, ikon centang + teks "Tersimpan"
      (hijau --color-accent NEVER satu-satunya penanda), tautan "Ganti" & "Hapus".
   c. Gagal — pesan menyebut SEBAB dan CARA MEMPERBAIKI:
      "Ukuran berkas 7&nbsp;MB, maksimal 5&nbsp;MB. Coba kompres atau unggah versi lain."
      NEVER "Upload gagal". Pesan muncul TEPAT DI BAWAH dropzone.
   Semua perubahan state diumumkan ke pembaca layar (anotasi: aria-live polite).

5. Just-in-time: sheet "Lampirkan CV" saat menekan Lamar pertama kali
   Bottom sheet (375px) / dialog (1440px) di atas Detail Lowongan.
   • Judul menyebut konteksnya: "Lampirkan CV untuk melamar di [Nama Perusahaan]"
   • Dropzone yang sama seperti artboard 3 (komponen dipakai ulang).
   • Alternatif jujur bila belum punya berkas: "Saya belum punya CV — isi data
     singkat" -> mengarah ke form profil terstruktur.
   • Scrim gelap 40–60%, sheet hormati safe area bawah (gesture bar).
   Ini artboard PALING PENTING di prompt ini: di sinilah motivasi user tertinggi.

6. Pengingat setelah dilewati — non-blocking
   Kartu tipis di halaman peta/profil: bar kelengkapan profil + daftar 3 item
   (foto · CV · lokasi domisili) dengan centang pada yang selesai, dan tombol
   tutup. NEVER modal, NEVER pemblokir.
   Gambar juga state "sudah 100%" — apresiasi singkat, lalu kartunya hilang.

7. Pemotongan foto (crop)
   Bottom sheet di 375px, dialog di 1440px. Bingkai lingkaran 1:1, slider zoom
   (target sentuh >=44px), tombol Batal / Pakai. Scrim 40–60%.

8. Peringatan "perubahan belum tersimpan"
   Dialog kecil saat user menekan kembali setelah mengubah nama / memilih foto
   tapi belum menyimpan: "Perubahan belum disimpan. Keluar?" -> Batal / Keluar.

[TEMPEL BLOK A DI ATAS DULU]

Desain KERANGKA (shell) halaman peta — yaitu semua yang mengelilingi peta.
Peta sungguhan TIDAK didesain di sini: interaksinya (clustering, pan/zoom,
hover sync) hanya bisa dinilai saat dikode. Gambar area peta sebagai
placeholder abu-abu dengan beberapa pin & cluster contoh, lalu fokuskan
desain pada bingkainya.

PENTING: selesaikan SEMUA artboard di bawah. Jangan berhenti di tengah.
Kalau jawabanmu akan terpotong, kerjakan per artboard dan sebutkan
sisanya — jangan tinggalkan artboard setengah jadi.

Artboard DESKTOP 1440px:
- Split view: daftar lowongan di kiri (lebar +-420px), peta di kanan.
- Header filter di atas: kategori, rentang gaji, tipe kerja, radius (slider km),
  tombol "Lokasi Saya".
- Daftar memakai JobCard dari DESIGN 1.
- Gambarkan state hover: satu job card sedang di-hover DAN pin pasangannya
  menyala di peta (beri anotasi panah untuk sinkronisasi dua arah ini).
- Tampilkan jumlah hasil ("48 lowongan di area ini") dan kontrol urutan.

Artboard MOBILE 375px — INI YANG PALING PENTING:
- Peta full-screen (100dvh, NEVER 100vh) + bottom sheet berisi daftar lowongan.
- Gambar bottom sheet dalam 3 posisi: tertutup (peek +-120px, menampilkan 1
  kartu), setengah (+-50%), penuh.
- Tombol filter mengambang & tombol "Lokasi Saya" — jangan sampai tertutup
  bottom sheet.
- Hormati safe area: kontrol NEVER bertabrakan dengan gesture bar Android/iOS.
- Sediakan alternatif tap DAN keyboard untuk semua gestur geser.
- overscroll-behavior: contain pada bottom sheet.

State yang MUST digambar:
1. Memuat — skeleton kartu, NEVER spinner kosong.
2. Kosong — "Belum ada lowongan di area ini" + saran memperluas radius.
3. Error — gagal memuat peta / lokasi ditolak browser, berisi cara memperbaiki.
4. Izin lokasi ditolak — jelaskan konsekuensinya & tetap sediakan pencarian manual.

Aturan wajib:
- Atribusi "© OpenStreetMap contributors" terlihat di peta (lisensi ODbL).
- Kontrol peta minimal 44x44px, ber-aria-label.
- Pin & cluster dibedakan BENTUK + ANGKA, NEVER warna saja.
- Beri anotasi: URL MUST mencerminkan state (filter, area, radius) agar bisa
  di-share & di-bookmark.
